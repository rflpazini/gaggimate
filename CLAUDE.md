## Project Overview

**GaggiMate** is an IoT project that upgrades Gaggia Classic espresso machines with smart electronic controls. It consists of:

- **Dual embedded firmware targets** (display unit + controller board) built with PlatformIO/Arduino on ESP32
- **A web interface** built with Preact + Vite + Tailwind CSS
- **A plugin system** for extensibility (BLE scales, MQTT/Home Assistant, Apple HomeKit, shot history, etc.)

## Build System

### Firmware — PlatformIO

The `platformio.ini` defines five environments:

| Environment | Board | Purpose |
|---|---|---|
| `display` | LilyGo-T-RGB | Main display with LVGL UI |
| `display-headless` | LilyGo-T-RGB | Headless variant (no graphics) |
| `display-headless-8m` | Seeed XIAO ESP32S3 | 8MB headless |
| `display-headless-4m` | ESP32-S3-SuperMini | 4MB headless |
| `controller` | Gaggimate-Controller | Controller board |

All firmware uses `espressif32@6.12.0`, Arduino framework, C++17, and `-Os` optimization.

### Web Interface — npm + Vite

The `web/` directory is a standalone Preact + Vite project.

```bash
cd web
npm install         # Install dependencies (requires Node 22 / lts/jod)
npm run dev         # Dev server at http://localhost:5173 (proxies /api and /ws to device)
npm run build       # Production build → dist/
npm run preview     # Test production build at http://localhost:4173
npm run format      # Apply Prettier formatting
npm run lint        # ESLint with auto-fix
npm run lint:check  # ESLint check only (no fix)
```

## Common Development Commands

### Build

```bash
# Build firmware
platformio run -e display
platformio run -e controller

# Build web UI and package into SPIFFS data image
scripts/build_spiffs.sh
```

### Flash to Device

```bash
# Display firmware
platformio run -e display -t upload -t monitor

# Controller firmware
platformio run -e controller -t upload -t monitor

# Web UI filesystem image
scripts/build_spiffs.sh
platformio run -e display -t uploadfs -t monitor
```

### Static Analysis

```bash
platformio check -e display
platformio check -e controller
```

### Format Code

```bash
# C/C++ — uses .clang-format (LLVM style, 4-space indent, 130 char column limit)
scripts/format.sh

# Web — uses .prettierrc (100 char width, 2-space indent, Tailwind plugin)
cd web && npm run format

# Markdown
npx prettier -w <file>.md
```

### Serial Monitor

```bash
platformio run -e display -t monitor   # 115200 baud, with esp32_exception_decoder
```

## Architecture

### Display Firmware

```
main() → controller.setup() → controller.loop()
  Controller (src/display/core/Controller.h)
    ├── WiFi / BLE connections
    ├── PluginManager — loads and drives plugins
    ├── ProfileManager — brew profile CRUD
    ├── Settings — persistent preferences (Preferences API + JSON)
    ├── DefaultUI — LVGL screen management and touch events
    └── Process — state machine for brew / steam / pump / grind
  Plugins (src/display/plugins/)
    ├── WebUIPlugin    — HTTP REST API + WebSocket server
    ├── MQTTPlugin     — Home Assistant autodiscovery
    ├── BLEScalePlugin — Bluetooth scale integration
    ├── ShotHistoryPlugin — Shot recording and indexing
    ├── HomekitPlugin  — Apple HomeKit via HomeSpan
    └── [8 more plugins]
  Event System (src/display/core/Event.h)
    └── Typed EventData (int / float / string values)
```

**Key source files:**

| File | Purpose |
|---|---|
| `src/display/core/Controller.h/cpp` | Main orchestrator |
| `src/display/core/Settings.h/cpp` | Persistent preferences, JSON serialization |
| `src/display/core/zones.h` | Temperature zone definitions |
| `src/display/core/ProfileManager.h/cpp` | Brew profile management |
| `src/display/core/process/BrewProcess.h` | Brew state machine |
| `src/display/core/Event.h` | Typed event system |
| `src/display/core/Plugin.h` | Plugin base interface |
| `src/display/plugins/WebUIPlugin.cpp` | REST API and WebSocket server |
| `src/display/plugins/ShotHistoryPlugin.cpp` | Shot recording and indexing |
| `src/display/ui/default/DefaultUI.h/cpp` | LVGL screen management |
| `lib/NimBLEComm/` | BLE protocol UUIDs and callbacks |
| `lib/GaggiMateController/` | Hardware peripheral control |

### Controller Firmware

Located in `src/controller/` and `lib/GaggiMateController/`. Manages hardware peripherals (heater, pump, solenoid valve), safety mechanisms (thermal runaway shutoff), and BLE communication with the display unit via NimBLE.

### Web Interface

```
App (Preact Router — web/src/index.jsx)
  ApiServiceContext — WebSocket client with exponential-backoff reconnect
  Pages: Home, ProfileList, ProfileEdit, Settings, OTA, ShotAnalyzer,
         ShotHistory, Statistics, Autotune, Scales
  Components: reusable UI widgets (Chart, Card, Navigation, …)
  State: Preact Signals (@preact/signals)
```

The web UI communicates with the device exclusively via WebSocket (`/ws`). The full protocol is documented in `docs/websocket-api.yaml` (AsyncAPI 2.6.0 spec).

## Coding Conventions

### C/C++

- **Style:** LLVM-based clang-format, 4-space indent, 130-character column limit
- **Standard:** C++17 (`-std=gnu++17`)
- **Naming:** `PascalCase` for classes, `camelCase` for methods/functions, `UPPER_SNAKE_CASE` for constants
- **Headers:** `#ifndef / #define / #endif` guards
- **Includes:** `<library.h>` for external, `"local.h"` for project-local files
- **Plugins:** Implement `virtual void setup()` and `virtual void loop()` from `Plugin.h`
- **Events:** Use `EventDataEntry` with typed int/float/string payloads
- **Logging:** Use `ESP_LOG*` macros (not `Serial.print`)

### JavaScript / Preact

- **Style:** Prettier, 100-character column limit, 2-space indent
- **Components:** Functional only (no class components), PascalCase filenames
- **State:** Preact Signals for reactive state; avoid unnecessary re-renders
- **Naming:** `camelCase` for functions/variables, `PascalCase` for components
- **Styling:** Tailwind utility classes + DaisyUI components; no custom CSS unless required
- **Modules:** ES modules (`import … from '…'`)

## CI/CD

Four GitHub Actions workflows in `.github/workflows/`:

| Workflow | Trigger | What it does |
|---|---|---|
| `check.yml` | Push / PR | `platformio check` static analysis on display + controller |
| `build.yml` | Git tag push | Builds all firmware variants, packages SPIFFS, creates GitHub release |
| `build-nightly.yml` | Schedule | Nightly build for regression testing |
| `pr-flash.yml` | PR | Validation build for PRs |

**Before opening a PR**, ensure:
1. `scripts/format.sh` produces no diff
2. `cd web && npm run lint:check` passes
3. `platformio check -e display` and `platformio check -e controller` pass

## Key Integrations & Protocols

- **BLE (NimBLE):** Display ↔ controller communication; see `lib/NimBLEComm/` for UUIDs
- **WebSocket API:** Full device control from the web UI; spec at `docs/websocket-api.yaml`
- **MQTT:** Home Assistant autodiscovery via `MQTTPlugin`
- **HomeKit:** Apple HomeKit via HomeSpan library (`HomekitPlugin`)
- **OTA:** HTTP and BLE firmware update paths
- **mDNS:** Device reachable at `gaggimate.local`
- **SPIFFS:** Web UI files stored on device flash; updated via `uploadfs`

```bash
# Analyze an ESP32 core dump

```

The monitor filter `esp32_exception_decoder` automatically decodes stack traces in serial output.
